# systemval

- Systemval guide (/kom-igang/systemval/) is config-driven: questions/modules in config.ts, deterministic routing in engine.ts; product modules plug into MODULES so the engine never needs rebuilding and UI holds no flow logic.
- Product modules live in modules/ and are registered in modules/index.ts; each module owns its questions, requestsCommon gating and a deterministic evaluate() whose output the page reads from state.moduleResults, so routing and assessment stay testable outside React.
- ERP assessment (modules/erp.ts) uses explicit rule objects with strength labels per dimension (Finance, SCM, comparison, context), never size/country/NAV/AX shortcuts or public scores; ERP8 is a configured template chosen from open uncertainty, not free AI, so outcomes are reproducible.
- Solution picture (solutions.ts) is a pure layer over DialogState + moduleResults that sorts areas into primary/complementary/investigate by signal kind (core/cross/hint), never highest-score-wins; it never alters routing, so dialog and result evolve independently.
- Optional deepening (deep.ts) is a separate short dialog driven by the solution picture: product tracks are interviewed only for primary areas (or the single area), combinations get cross-area questions instead; it outputs a structured Handover stored locally for later tools so buyers are never asked twice.
- Service module (modules/service.ts) owns the Customer Service / Contact Center / Field Service assessment; when active, solutions.ts ignores need/problem heuristics for cs/cc/fs so channel, phone, field work or data needs never become product recommendations on their own.
- Project Operations module (modules/projectOperations.ts) owns the po assessment when active; working in projects, finance-only or internal projects never yield po, and an ERP gränsfall becomes an alternative, not a choice.
- Solution map (solutionMap.ts) is a pure layer over SolutionPicture + moduleResults classifying start/alternatives/complements/later/dependencies; later phase only with explicit priority and no process dependency, so no roadmap is invented.
